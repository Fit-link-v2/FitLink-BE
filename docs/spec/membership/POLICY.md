# 회원 도메인 정책

> 코드가 **지금 실제로 지키는** 규칙을 적는다. 기능이 머지될 때 doc-sync에서 채운다. 설계상 규칙은 진행 중인 기능의 개발 PRD에 있다.

## 규칙

### 회원

- 강사는 이름만으로 회원을 추가한다. 메모는 선택이다. 이름은 앞뒤 공백을 지운 뒤 1 ~ 50자, 메모는 500자 이하이고 빈 메모는 메모가 없는 것과 같다
- 같은 이름의 회원을 여러 명 둘 수 있다. 구분은 메모로 한다
- 회원을 추가하면 같은 요청에서 개인 링크가 발급된다. 링크 저장이 실패하면 회원도 남지 않는다
- 이름 · 메모 · 상태는 보낸 것만 바꾼다. 이름과 상태는 지울 수 없고, 메모는 `null` · 빈 문자열로 지운다
- 수강 종료(ENDED)는 삭제가 아니다. 회원 행과 링크가 그대로 남고, 다시 ACTIVE로 되돌릴 수 있다
- 다른 강사의 회원과 없는 회원은 같은 404다

### 개인 링크

- 링크는 `{회원 화면 주소}/m/{토큰}`이다. 토큰은 16바이트 암호학적 난수를 base64url(패딩 없음)로 쓴 22자다
- 서버에는 토큰의 SHA-256만 남는다. 원본은 발급 응답에만 실리고, 그 응답은 `Cache-Control: no-store`다. 로그 수준을 TRACE까지 낮춰도 로그에 원본이 찍히지 않는다
- 회원 1명에게 살아 있는(끊지 않은) 링크는 1개다
- 재발급은 살아 있는 링크를 끊고(끊은 시각을 남긴다) 새 링크를 만든다. 수강 종료 회원도 재발급한다. 같은 회원의 재발급이 동시에 와도 차례로 돌아 둘 다 성공하고 마지막 링크만 산다

### 회원 목록

- "링크를 열었다"는 살아 있는 링크를 연 기록이 있는지다. 재발급하면 이전 링크를 열었어도 다시 "열지 않음"이다
- 순서는 링크를 열지 않은 ACTIVE → 나머지 ACTIVE → ENDED이고, 묶음 안은 이름의 문자 코드 순(한글은 가나다 순, 영문은 대문자 먼저), 같은 이름은 먼저 추가한 회원이 먼저다
- 링크를 열지 않은 회원 수는 ACTIVE만 센다

## 하지 않는 것

- 회원을 지우는 경로가 없다
- 연락처(전화번호 등)를 받지 않는다
- 서버에 토큰 원본이 없으므로 발급한 링크를 다시 보여 주지 않는다. 다시 보내려면 재발급한다
- 수정 요청의 모르는 필드는 무시한다(오타도 200)

# 시간표 도메인 정책

> 코드가 **지금 실제로 지키는** 규칙을 적는다. 기능이 머지될 때 doc-sync에서 채운다. 설계상 규칙은 진행 중인 기능의 개발 PRD에 있다.

## 규칙

날짜 · 시각은 서울 기준이다. "지금" · "오늘"은 요청이나 작업을 시작할 때 한 번 읽은 값을 끝까지 쓴다. 자정 작업만은 스케줄러가 조금 일찍 깨어나도 새 날을 오늘로 보도록 1분 뒤 시각의 날짜를 오늘로 쓴다.

### 반복 규칙

- 강사는 요일 · 시작 시각 · 정원(1 ~ 50)으로 매주 여는 수업을 정한다. 요일을 여러 개 고르면 요일마다 규칙이 하나씩 생긴다. 같은 요일을 두 번 보내면 400이고 아무것도 저장하지 않는다
- 같은 강사 · 요일 · 시각에 켜진 규칙은 하나다. 여러 요일 중 하나라도 겹치면 전부 저장하지 않고 겹친 요일을 알려 준다. 동시에 들어온 요청이 DB 제약에 걸리면 409이지만 겹친 요일 목록은 비어 있다
- 규칙을 끄면 이미 만든 회차는 그대로 두고 이후 생성만 멈춘다. 다시 켜면 바로 오픈 범위 안의 회차를 만든다
- 꺼진 규칙의 오늘 이후 회차는 같은 요일 · 시각의 켜진 규칙이 이어받는다. 시각 · 휴강 · 정원은 그대로이고, 그 날짜에 회차를 새로 만들지 않는다

### 회차 생성

- 켜진 규칙마다 오픈 범위 `[오늘, 오늘 + N일)` 안의 그 요일에 회차를 하나씩 만든다. 시작 시각이 지금 이전이면 만들지 않는다
- 회차의 정원은 만들 때의 규칙 정원을 복사한다. 규칙을 끄고 같은 요일 · 시각에 정원이 다른 새 규칙을 켜도, 이미 만든 회차(이어받은 회차 포함)의 정원은 그대로다
- 같은 강사 · 같은 시각에 슬롯이 이미 있으면 휴강한 슬롯이라도 만들지 않는다. 강사가 휴강하거나 옮긴 회차를 다시 채우지 않는다
- 여러 번 돌아도 결과가 같다
- 언제 도는가: 규칙 등록 · 다시 켜기 · 오픈 범위 늘리기 요청 안(그 강사), 매일 0시(서울)와 앱 시작 때(모든 강사). 자정 · 앱 시작 생성이 실패하면 로그만 남기고 다음 실행이 채운다

### 슬롯 조회 · 변경

- 강사 슬롯 목록은 지금 이후 자기 슬롯 전부다. 휴강한 슬롯과 오픈 범위 밖에 남은 슬롯도 들어 있다
- 다른 강사의 슬롯과 없는 슬롯은 같은 404다
- 회차의 시각은 같은 날 안에서만 바꾼다. 일회성 수업은 오픈 범위 안의 다른 날로도 옮긴다
- 날짜를 보내지 않거나 지금과 같은 날짜를 보내면(반복 회차 포함) 범위를 보지 않는다. 범위를 줄여 범위 밖에 남은 슬롯도 시각은 바꿀 수 있다
- 휴강한 슬롯 · 시작한 슬롯 · 예약이 있는 슬롯은 시각을 바꿀 수 없다. 새 시각이 지금 이전이거나, 같은 시각에 휴강 아닌 수업이 있어도 안 된다
- 휴강은 행을 남기고 휴강 시각만 적는다. 다시 휴강해도 처음 시각 그대로이고, 되돌리지 않는다. 시작한 수업은 휴강할 수 없다. 예약이 있어도 휴강한다

### 일회성 수업

- 날짜 · 시작 시각 · 정원(1 ~ 50)으로 연다. 날짜는 오픈 범위 안, 시작 시각은 지금 이후여야 한다
- 같은 강사 · 같은 시각에 휴강 아닌 수업이 있으면 열 수 없다. 휴강한 시각과 다른 강사의 같은 시각에는 열 수 있다

## 하지 않는 것

- 격주 · 월 n번째 주 같은 반복은 없다. 반복은 매주로 고정이다
- 규칙의 요일 · 시각 · 정원을 고치거나 규칙을 지우는 경로가 없다. 끄고 새로 등록한다
- 오픈 범위를 줄여도 범위 밖 슬롯을 지우지 않는다
- 휴강을 되돌리거나 슬롯을 지우는 경로가 없다
- 반복 회차를 다른 날로 옮기지 않는다
- 23:59에 오픈 범위를 늘리는 요청이 자정 작업보다 늦게 커밋되면 새 범위의 마지막 하루가 다음 실행까지 빈다. 막지 않는다

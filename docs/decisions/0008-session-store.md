# 강사 세션 저장소는 직접 만든 `instructor_session` 테이블로 한다

## 맥락

DEC-0002는 "세션은 DB에 저장하고, 세션 ID는 해시로 저장한다"고 정했다.

Spring Session JDBC는 세션을 DB에 저장해 주는 공식 모듈이다. 그런데 공식 문서의 PostgreSQL 스키마는 `SPRING_SESSION` 테이블에 `SESSION_ID CHAR(36)`을 **원본 그대로** 저장한다. 그대로 쓰면 "해시로 저장"을 지킬 수 없다.

## 결정

세션 저장소를 직접 만든다. 테이블은 `instructor_session`이고 정의는 [BE-0001](../spec/instructor/0001-instructor-setup/prd.md)에 있다.

- 세션 ID 원본은 쿠키에만 있고, DB에는 SHA-256 해시(`session_hash`)만 저장한다
- 발급 · 조회 · 연장 · 로그아웃 · 만료 정리를 직접 구현한다. `HttpSession`은 쓰지 않는다
- 로그인 흐름도 같은 이유로 직접 구현한다(BE-ADR-0014)

## 검토한 대안

| 대안 | 버린 이유 |
|---|---|
| Spring Session JDBC | 세션 생성 · 만료 · 정리가 이미 구현돼 있다. 그러나 세션 ID를 원본으로 저장한다. 해시로 저장하려면 저장소를 커스터마이즈해야 하고, 그 범위가 직접 구현과 비슷하다 |
| Spring Session JDBC를 쓰고 "해시로 저장"(DEC-0002)을 바꿈 | DB가 유출되면 살아 있는 세션을 그대로 가져갈 수 있다. 회원 링크 토큰도 해시로 저장하는데 세션만 예외가 된다 |

## 대가

- 쿠키 발급 · 조회 · 연장 · 로그아웃 · 만료 정리를 직접 구현하고 테스트한다
- 세션 고정 방지(로그인마다 새 세션 ID, DEC-0008)를 프레임워크가 해 주지 않는다. 구현에서 지킨다
- 요청마다 만료를 연장하므로 요청마다 쓰기가 한 번 생긴다. 부담이 되면 `last_seen_at`이 일정 시간 이상 지났을 때만 갱신한다
